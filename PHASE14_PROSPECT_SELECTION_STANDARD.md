# Bonebrake Web Design — Strict Prospect Selection Standard

**Status:** AUTHORITATIVE

From this point forward, use the following rules whenever finding businesses for Bonebrake Web Design.

The goal is **not** to find good businesses with merely average websites.

The goal is to find **good, active businesses whose websites are clearly bad enough, outdated enough, or poorly designed enough that a professional rebuild would create an obvious and dramatic improvement.**

## 1. Business quality

Only select **active A-tier or strong B-tier businesses**.

The business should show clear evidence that it is legitimate and currently operating, such as:

- Recent customer reviews
- Active phone number
- Current business listings
- Recent social activity or business activity when available
- Established operating history
- Real customers/projects/services
- Good reputation or meaningful review volume
- Evidence the company can realistically afford a professional website

Avoid dead businesses, hobby businesses, extremely new companies with no track record, or businesses that appear financially weak.

## 2. Website creation / rebuild window — HARD GATE

The prospect's **current live website must have been originally created, launched, or last meaningfully rebuilt between January 1, 2022 and December 31, 2025 inclusive.**

This is a **hard eligibility requirement**, not a preference.

Immediately reject or skip a prospect when:

- The current website was clearly created or meaningfully rebuilt before 2022.
- The current website was clearly created or meaningfully rebuilt after 2025.
- The website's creation/rebuild year cannot be reasonably verified as 2022, 2023, 2024, or 2025.

Do **not** rely only on a copyright year in the footer. A dynamically updated `2026` footer does not prove the website was created or rebuilt in 2026, and an old footer does not by itself prove an old build.

Verify the 2022–2025 window using multiple credible indicators when available, such as:

- Archived website snapshots and visible redesign changes
- Technology/framework or template generation clues
- Page/content publication dates
- Metadata and structured data
- Launch or redesign announcements
- Domain/site history
- Dated staff, project, service, news, or portfolio content
- Image/media timestamps or asset-generation clues
- Search-index evidence showing when the current design first appeared

The system must record the **verified current website creation/rebuild year** for every prospect that advances. If the year is uncertain, **reject rather than guess**.

## 3. Website must actually need a redesign

This is a **HARD requirement**.

Do **not** select a company simply because its website could be “a little better.”

The website should have multiple significant weaknesses such as:

- Visibly dated design
- Poor mobile experience
- Weak typography
- Bad spacing
- Cluttered layouts
- Tiny text
- Poor image presentation
- Low-quality or stretched images
- Confusing navigation
- Weak homepage hierarchy
- No clear primary CTA
- Contact information difficult to find
- Services poorly organized
- Important trust signals buried
- Reviews/testimonials poorly presented
- Licenses/accreditations hidden
- Poor color choices
- Visually inconsistent sections
- Outdated visual effects
- Excessive empty space
- Overcrowded pages
- Desktop-only feeling on mobile
- Broken responsive behavior
- Old-fashioned navigation
- Poor conversion structure
- Homepage does not clearly explain what the business does
- Website makes the company look less professional than the actual company is
- Clearly inferior to modern competitors in the same market

Evaluate the website like a professional web designer, UX designer, conversion specialist, and potential customer.

Ask:

> **Would a normal customer immediately notice a major improvement if Bonebrake rebuilt this?**

If the answer is not clearly **YES**, reject the prospect.

## 4. Redesign delta must be large

This is one of the most important variables.

Estimate:

**Current website quality → realistic Bonebrake redesign quality**

A large visual and functional gap is required.

Examples:

- Current site 3/10 → Bonebrake can make 8.5/10 = excellent prospect
- Current site 4.5/10 → Bonebrake can make 9/10 = excellent prospect
- Current site 6/10 → Bonebrake can make 8.5/10 = questionable
- Current site 7/10 → Bonebrake can make 9/10 = reject

Do **not** waste time redesigning websites that are already good.

A website similar to Dardon Construction’s current site should generally be **rejected** because it is already functional and professionally acceptable, even if improvements are possible.

## 5. No under-construction websites

Immediately reject:

- “Coming soon”
- “Website under construction”
- Temporary landing pages
- Placeholder sites
- Parked domains
- Recently launched unfinished websites
- Businesses obviously already in the middle of a redesign

We want companies with **existing bad websites**, not companies already replacing them.

## 6. Verify the business before building anything

Before creating a redesign, research:

- Business status
- Current website
- Verified website creation/rebuild year
- Services
- Location/service area
- Reviews
- Reputation
- Company history
- Contact information
- Public project imagery
- Branding/assets
- Competitor website quality

Never generate the redesign first and investigate afterward.

## 7. Compare them to competitors

Examine several modern competitors in the same market.

Determine whether the prospect’s website makes them look materially worse online than companies they compete against.

This is a strong buying signal.

Example: the company may actually be excellent, but if three competitors have modern professional sites while their site looks materially weaker, that is exactly the type of opportunity we want — provided the current website also passes the 2022–2025 creation/rebuild hard gate.

## 8. Require multiple website problems

Do not qualify a prospect because of one minor flaw.

Normally require at least **3–5 meaningful website deficiencies**.

At least one should ideally be substantial:

- Major visual age
- Poor mobile UX
- Serious conversion weakness
- Confusing information architecture
- Weak credibility presentation

## 9. Prospect scoring

Score candidates out of 100.

| Variable | Weight |
| --- | ---: |
| Active/credible business | 20 |
| Business reputation/reviews | 10 |
| Ability to reasonably purchase a ~$2,000 website | 10 |
| Website visual/design weakness | 20 |
| Mobile/UX weakness | 10 |
| Conversion/CTA weakness | 10 |
| Redesign delta | 15 |
| Contactability/assets available | 5 |
| **Total** | **100** |

Qualification:

- **90–100: A+** — immediately worth pursuing
- **82–89: A** — strong prospect
- **75–81: B** — acceptable if the website problems are obvious
- **Below 75: reject**

However, **a high business-quality score can never compensate for a website that is already good or a website outside the required 2022–2025 creation/rebuild window.**

If the website does not clearly need a rebuild, or the website-age hard gate fails, reject it regardless of total score.

## 10. Final human-style test

Before selecting any prospect, answer these questions:

- Is the business definitely active?
- Is it a legitimate A/B-tier company?
- Is the current website reasonably verified as created/launched/meaningfully rebuilt in **2022, 2023, 2024, or 2025**?
- Does the website look meaningfully outdated or poorly designed?
- Can I identify specific professional reasons the website needs replacement?
- Would a before/after comparison be dramatic?
- Is the business likely capable of paying approximately $1,995?
- Can Bonebrake create something clearly superior using available business information/assets?
- Is the company **not** already redesigning its website?

Every important answer should be **YES**.

If there is doubt, **skip the business and find a better one**.

## 11. Outbound email visual-proof hard gate

Every cold outbound email that says or implies a visual sample is included must pass this gate **before Gmail send is invoked**.

- Never use a GitHub-hosted, CDN-hosted, or other remote SVG as the prospect-facing email image.
- Never rely on an externally hosted `<img src="https://…">` as the sole proof sample.
- Render the approved concept sample to a real **PNG or JPEG** before constructing the email.
- Preferred email sample width is **600–800 px**.
- Preferred encoded file size is **200–500 KB**; optimize as needed while keeping the concept legible. A sample outside that target may be used only when necessary, but it must remain below 1 MB.
- The exact raster file sent must be preserved as outreach evidence and linked to the immutable design version.
- Construct the Gmail message with that raster file as an actual MIME attachment or true inline MIME image. For the connected Gmail sender, `attachment_files` is the default safe path unless inline-CID delivery is explicitly supported and verified.
- The pre-send payload must contain at least one real media file and the filename must end in `.png`, `.jpg`, or `.jpeg`.
- If the image file cannot be materialized, attached, or embedded, **do not send the email**. Mark the prospect pipeline blocked/failed at EMAIL QA instead.
- SVG may still be retained as a source artifact for design work, but it is **not an allowed outbound email delivery format**.

Immediately after each send, read the authoritative Gmail message and verify at least one of the following is true:

1. `has_attachment=true` with the expected PNG/JPEG in `attachments`, or
2. the expected PNG/JPEG appears in `inline_images` as a real MIME part.

If neither is true, the send must **not** be logged as media-verified. Record the delivery defect truthfully in `prospect_outreach_events` and block any additional automated outreach to that prospect pending owner review. Never claim a visual sample was delivered when Gmail evidence does not show it.

For every successful `sent` outreach event, preserve these media facts in the Control Center evidence:

- sample filename
- MIME type
- byte size
- raster width
- delivery mode (`attachment` or `inline`)
- `gmail_media_verified=true`
- Gmail message ID and thread ID

## Core rule

> **GOOD BUSINESS + BAD WEBSITE + VERIFIED 2022–2025 CURRENT SITE = PROSPECT.**
>
> **WEBSITE OUTSIDE 2022–2025 OR AGE NOT VERIFIABLE = REJECT.**
>
> **GOOD BUSINESS + GOOD WEBSITE = LEAVE THEM ALONE.**
>
> **BAD BUSINESS + BAD WEBSITE = LEAVE THEM ALONE.**

We are looking specifically for established businesses whose real-world quality is substantially better than their online presentation, while enforcing the required website creation/rebuild window.

**Quality over volume. Never select somebody simply because an hourly prospecting slot needs to be filled.**
